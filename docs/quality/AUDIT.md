# P0-Quality 现状审计

2026-10-31；审计对象：PR #1 当前P0-A代码，源头68a07e3。依据：用户亲自试玩反馈及src/game/world.ts、src/main.ts、tests/browser/game.spec.ts静态审阅。未进行新的在线操作或性能采样。

## 结论
P0-A只完成技术验证，产品体验验收未通过。现有截图里的格子色块、三角人物和山体全部是调试占位，不能视为正式美术。单元测试、页面可加载和地图显示不能证明美术、节奏、策略或商业品质合格。

## 证据、影响和处理
| 项 | 代码事实或现有证据 | 体验影响 | 决策 |
|---|---|---|---|
| 地图 | terrain用坐标条件定义两块矩形山体；山路恒为y=9/10；固定30×18格 | 路线人工感强，无场景构图或探索层次 | 保留地形类别与不可通行契约；地图数据改为人工布局、独立通行蒙版，支持镜头滚动 |
| 寻路 | 四邻BFS；护卫/敌人每帧清空路线并重新寻路；跟随目标仅按唐僧世界x偏移 | 转弯队形不沿道路，易重叠或折返；高敌数下重复计算可能增加开销（未测量） | 保留可达性测试；引入缓存/目标变化重算、路径平滑、沿领队路径的槽位与局部分离，先测后优化 |
| 渲染 | Phaser Graphics逐帧重绘地形；labels每帧destroy并add.text；stats每帧innerHTML | 无正式动画；对象分配与文字渲染存在潜在性能风险（没有FPS实测） | Phaser保留；静态地图分层缓存、atlas精灵、持久文本；镜头外裁剪与特效池 |
| 美术 | 人物三角身体、圆头；无sprite/动画资源；马与唐僧位置重合但无骑乘动作系统 | 辨识度、动作、材质和细节不足 | 原创角色标准稿与动画资源替换；不把程序几何素材包装成正式资源 |
| 刷怪 | spawnTimer初始4秒，其后固定7秒；spawn只有一种65HP近战白骨兵 | 单个送怪，缺少波次、远程与夹击 | 废除固定单怪计时器，数据驱动剧情波次+多出生区+威胁预算 |
| 敌方目标 | 有近身护卫则取数组首个；否则骑乘时统一打马，马死后才打唐僧 | 无敌人种类策略，唐僧危险主要依赖先杀马；缺少可读的突破保护 | 按兵种实现护卫牵制、迂回与远程威胁，明确唐僧可被攻击；不靠直接扣血制造难度 |
| 自动护卫 | 三名战斗角色共享选敌逻辑，均按敌人与唐僧距离排序 | 八戒前拦截、沙僧后防守差异不足 | 角色护卫职责、拦截槽位与目标保留；悟空离队时护卫压力可观测 |
| 攻击 | 距离满足且cooldown<=0即扣血；无前摇/命中/后摇事件 | 没有打击节奏或躲避判断依据 | 独立动作状态机，以命中时间点结算、同步音画反馈 |
| 避险 | 唐僧每帧枚举局部候选；无安全路径与护卫圈评分 | 可能无意义折返；该问题尚待录屏复现 | 危险评分、滞回与短期目标承诺；保留手动目的地，紧急躲避后恢复 |
| 死亡复活 | 唐僧死亡冻结；其他4角色35共享灵力、3秒后复活；马死降低唐僧速度 | 核心规则正确，可复用；复活坐标重叠需改善 | 保留方案B、能量与延迟契约；增加安全落位与动作，不改失败条件 |
| 操作 | 角色按钮持久节点、aria-pressed、点击地面和拒绝白马独立命令 | 修复可保留；缺少技能反馈、速度档位与滚动镜头输入变换 | 保留交互契约，新增镜头坐标转换、明确选中/路径/危险层 |
| 测试 | 覆盖按钮、唐僧绕山、复活、失败、单兵护卫；部分场景通过test接口布置 | 无正常流程失败、密集围攻、难度差异、动画、声音或性能证据 | 旧回归保留；新增自然失败、可赢路径、波次/状态机与性能证据 |
| 部署 | Private仓库、现有PR、Vercel受保护分支预览、npm ci与dist | 可继续迭代；登录后的在线交互未由代理完整验证 | 原样保留；不动工业网站/main/Production |

## 不做全部重写
保留World模拟接口、角色ID、生命/伤害/方案B规则、地形类别、command/regroup/revive交互、Phaser/TS/Vite、锁文件、自动构建、浏览器回归与受保护部署。将大文件按职责渐进拆分：map/navigation、escort、combat/actions、encounters、story、presentation、audio、HUD。先加契约回归，再替换一个子系统，避免同时重做架构和全部玩法。

## 先修的结构风险
1. 先从渲染中抽离静态地图与持久文本，避免新增精美资源后仍逐帧创建对象。
2. 统一世界坐标、碰撞蒙版、角色脚点和镜头坐标；人工地图边界与可通行区域逐块复核。
3. 战斗时间使用固定模拟步进/累积器；1×/2×仅缩放模拟时间，不能跳过前摇、重复命中或改变复活成本。
4. 布防和剧情触发配置化，保留后续动态建筑、幻象生成与消散接口。
5. 12—25敌人上限不是性能承诺：先采样寻路耗时、对象数与帧时间，再决定网格分辨率和重算频率。

## 尚不能下结论的事项
没有本轮FPS、输入延迟、长局胜率或正式美术实机录屏，不能声称不卡顿、平衡合理或达到Kingdom Rush商业水准。依赖告警见现有QA，未在本次文档审计中执行升级。
